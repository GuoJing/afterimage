# 后台用户管理

## 功能

- 后台侧栏新增“用户管理”，地址为管理员私有前缀下的 `/users`。
- 用户列表显示头像、昵称、登录名、邮箱、等级和封禁状态。
- 管理员可以新增用户，或编辑登录名、昵称、邮箱、会员等级和状态。
- 会员等级只接受整数 0–5，前端使用固定下拉框，后端再次严格校验。
- 状态使用已有 `users.status`：`active` 为正常，`disabled` 为封禁。
- 封禁用户后不能登录；状态或邮箱改变时 `session_version` 增加，旧会员 Session 立即失效，未使用的重置链接也会作废。
- 管理员不能查看或直接填写用户密码。

## 新增用户与密码

新增用户时写入 `pending$<随机值>` 形式的不可用凭据，不存在管理员知道的初始密码。正常状态的用户创建后，系统自动向注册邮箱发送密码设置链接；封禁状态的用户不会收到可用链接。

编辑页的“发送密码重置邮件”复用公开忘记密码的安全机制：

- 256 位随机 token，数据库只存 SHA-256 摘要。
- 30 分钟过期、一次性使用。
- 邮件成功发送后，同一用户之前尚未使用的链接失效。
- 邮件发送失败时新 token 会失效，但不会误伤之前仍有效的链接。
- 管理员发信按邮箱 2 分钟冷却、每邮箱每小时 3 次、每管理员 IP 每小时 20 次以及全局每小时 100 次限制。
- 路由受后台 2FA 会话和 CSRF 保护，表单前端防止重复提交。

## 数据库

本功能复用现有 `users` 与 `password_reset_tokens`，没有新增表或字段，不需要额外数据库迁移。部署本批改动时，仍需确保上一批忘记密码功能的自动迁移已在应用启动时执行。

## 相关文件

- `server.js`：用户管理路由、校验、保存、封禁和重置邮件逻辑。
- `lib/member-security.js`：管理员触发重置邮件的独立限流。
- `views/admin/users.ejs`：用户列表。
- `views/admin/user-form.ejs`：新增与编辑表单。
- `views/admin/sidebar.ejs`：后台入口。
- `public/style.css`：桌面与移动端样式。
